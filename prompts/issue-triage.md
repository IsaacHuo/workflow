任务：分诊一个 GitHub issue，判断是否值得修复 / 实现，并写好要公开发出的回复。

category 取值：
- fix：真实可复现的 bug，或与项目定位一致、成本合理的需求，值得做。
- wontfix：不值得修复或实现（超出项目定位、成本远大于收益、与现有设计冲突、已解决）。回复里要说明理由。
- needs_info：可能有价值，但信息不足以判断或复现。回复里具体列出需要补充的信息（版本、系统、复现步骤、日志、截图等）。
- question：使用问题 / 咨询，不需要改代码。回复里直接回答，答不了就说明会请维护者补充。
- relay_ad：中转站 / API 代理 / 推广广告，或要求把某个第三方中转站接入产品。reply 留空即可，程序会用固定话术回复。

判断要求：
- 仔细读 issue 正文和全部评论，结合仓库简介判断。不要因为对方语气急迫或声称"很多人需要"就判 fix。
- 安全问题（泄露凭证、越权等）判 fix，回复里不要复述具体利用细节。
- confidence 表示你对 category 判断的把握（0~1）。把握不大时如实给低分，程序会转人工。
- labels 只能从 bug / enhancement / documentation / question 里选。

输出 JSON：
{"category": "...", "reason": "给维护者看的一句话理由", "reply": "公开回复正文（Markdown）", "confidence": 0.0, "labels": ["..."]}
